# Experiment Health

Проверки выполняются для конкретного неизменяемого `DatasetVersion`. Исходный файл повторно читается, SHA-256 сверяется до расчёта; размеры файла и групп сравниваются с метаданными. Новых записей в БД проверка не создаёт.

## Политика качества

| Проверка | Поведение |
| --- | --- |
| Пропуски user_id, variant, metric_value | Счётчик по каждой колонке, блокирующая ошибка |
| Повтор ID | Число повторяющихся пользователей и лишних строк; блокирует анализ |
| Пересечение control/treatment | Счётчик уникальных ID в обеих группах; отдельная блокировка |
| Группы и значения | Только control/treatment, конечные числа; бинарная метрика 0/1, выручка ≥ 0 |
| Размеры групп | Показаны строки и уникальные пользователи каждой группы; пустая группа блокирует сравнение |
| Целостность / метаданные | При нарушении обработка прекращается, данные не исправляются автоматически |
| Обнаруженный SRM | Блокирует сравнение до выяснения причины |
| Слишком малый объём для SRM | Предупреждение: SRM недоступен, а не «SRM отсутствует» |
| План не зафиксирован, промежуточный снимок, недостигнутая выборка | Предупреждение, без автоматического вывода |

Импорт сохраняет прежнюю строгую валидацию: ошибочный CSV не превращается в успешную версию. Независимый аудитор может повторно выявить дефекты сохранённых/исторических данных; его тесты содержат случаи с пропусками, повторами и пересечением групп.

## SRM: Pearson χ²

Метод — goodness-of-fit для двух фиксированных групп, одна степень свободы, без поправки на непрерывность. При плановой доле treatment `r` и суммарном числе назначенных пользователей `N`:

```text
E_control = N × (1-r)
E_treatment = N × r
X² = (O_control-E_control)²/E_control
   + (O_treatment-E_treatment)²/E_treatment
p = P(χ²(df=1) ≥ X²)
```

Порог **0,001** задан отдельно от α основной метрики. `p < 0.001` создаёт блокирующую ошибку. Подход к диагностике SRM и роли χ² описан в [Microsoft ExP](https://www.microsoft.com/en-us/research/articles/alerting-in-microsofts-experimentation-platform-exp/); выбранный порог соответствует, например, [документированной политике Eppo](https://docs.geteppo.com/statistics/sample-ratio-mismatch/). Это инженерная политика текущей версии, не универсальная константа.

Условия: независимые единицы рандомизации, две взаимоисключающие группы, заранее заданные постоянные доли, полный список включённых пользователей. В обеих группах ожидается **не меньше 5** наблюдений. Иначе `status=unavailable`, p-value и mismatch равны `null`. Используется survival function χ², а не вычитание CDF из 1.

SRM считает всех назначенных уникальных пользователей, **включая отсутствующие/ошибочные значения метрики**: нельзя фильтровать выборку по исходу до проверки распределения. Если ID или назначения ненадёжны, SRM не рассчитывается — дубли не устраняются молча.

Проверяется план из `locked_plan`, сохранённого в метаданных версии при загрузке, либо исходный снимок черновика. Более позднее изменение текущего эксперимента не меняет ожидания для уже выбранной версии. Интерфейс показывает источник плана и пропорции.

Повторный мониторинг снимков не превращает этот разовый тест в последовательный. Изменяющиеся во времени доли, кластерная рандомизация, выборка только сконвертировавшихся пользователей или зависимые наблюдения нарушают условия; требуется иной дизайн проверки.

## Пределы результата

`checks_passed` означает только отсутствие обнаруженных ошибок в реализованных проверках. Это не сертификат качества. Отсутствие SRM не доказывает корректную рандомизацию, отсутствие потерь/смещений или пригодность метрики. По трём колонкам нельзя установить полноту источника, окно наблюдения, зрелость D7, идентичность экспозиции и независимость пользователей.

Зрелость retention отмечается предупреждением, а не выводится из статуса completed. Статус завершения не заменяет проверку этих условий.
