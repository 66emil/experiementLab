# Планирование выборки

Первый реализованный метод оценивает выборку для **двух независимых пропорций**, распределённых **50/50**, при двусторонней проверке и ожидаемом росте конверсии. Это приближённый расчёт для планирования, а не анализ результата эксперимента.

При исходной конверсии `p1`, относительном MDE `r` и ожидаемой конверсии `p2 = p1 × (1 + r)`:

```text
p_bar = (p1 + p2) / 2
n = ceil(
  [z_(1-alpha/2) × sqrt(2 × p_bar × (1-p_bar))
   + z_power × sqrt(p1 × (1-p1) + p2 × (1-p2))]²
  / (p2-p1)²
)
```

`n` — наблюдения в каждой группе. MDE **относительный**: 10% → 11% означает +10% относительно исходной конверсии, или +1 процентный пункт.

Пример: baseline 10%, relative MDE 10%, α 5%, power 80% → **14 751 на группу**, **29 502 всего**.

Допущения: независимые Bernoulli-наблюдения, фиксированный горизонт, одна основная гипотеза, отсутствие промежуточного подглядывания и поправок на множественные сравнения. Для редких событий и малых выборок нормальная аппроксимация может быть неточной. Формула не предназначена для непрерывных метрик, кластерной рандомизации и отношения двух случайных величин.

В форме черновика доступен предпросмотр; сохранение конфигурации автоматически рассчитывает и сохраняет `planned_sample_size` при совместимых параметрах. В карточке и на `/planning?experiment=<id>` расчёт использует сохранённые baseline, эффект, α и мощность и записывает результат в эксперимент. Сервер проверяет бинарный тип метрики, доли 50/50 и единицу рандомизации `user`. Несовместимый план сохраняется только в черновике и блокирует запуск.

При переходе в running весь план, рассчитанная выборка и идентификатор метода сохраняются в `locked_plan`. Пересчёт или редактирование после запуска запрещены. Самостоятельный калькулятор `/planning` остаётся отдельным инструментом без сохранения в эксперимент. Плановые даты не являются автоматическим правилом остановки; доступны ручные переходы статусов.

Метод изолирован в `packages/statistics`, не использует случайность и проверяется на фиксированном числовом примере, ошибочных входах и свойствах монотонности. Сравнение метрик описано в [методах анализа](analysis-methods.md), SRM — в [проверках качества](health.md).
